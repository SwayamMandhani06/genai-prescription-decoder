This directory hosts the reproducible dataset infrastructure, ground-truth schemas, machine-readable manifests, deterministic splits, and validation tooling for **AURA-Rx: Explainable Multimodal AI for Handwritten Prescription Understanding**.

## 2. Privacy & De-Identification Protocol

Prescription documents can inherently contain Protected Health Information (PHI) / Personally Identifiable Information (PII). AURA-Rx enforces strict statutory and institutional safety controls:

1. **Zero Real Patient PII in Repository:**
   - No real patient names, home addresses, phone numbers, Aadhaar/SSN IDs, or personal hospital registration numbers are committed to version control.
   - All evaluation samples in `data/samples/` use synthetic or de-identified anonymized patient personas (`Patient: Anonymous Adult`, age, generic outpatient IDs).
2. **Ground Truth Certification (`patient_deidentified`):**
   - The annotation schema strictly mandates `patient_deidentified: true`. If set to `false`, automated validators reject the document with a `PII_RISK_IDENTIFIED` critical error.
3. **Physical Image Integrity Contract:**
   - While patient identifiers are de-identified or redacted, the **prescribed clinical doctor handwriting strokes must never be synthetically altered or beautified**. The 1:1 spatial ink relationship required for clinical verification remains strictly preserved.

## 3. Annotation Schema & Label Tiers

The annotation schema strictly separates four distinct semantic tiers:

1. **`GroundTruthAnnotation` (`tier: "ground_truth"`):**
   - Verified transcription of physician handwriting ink, captured at the document and line-item level. Includes exact transcribed tokens, standardized drug names, dosages, frequencies, and ambiguity ratings.
2. **`DerivedAnnotation` (`tier: "derived"`):**
   - Downstream deterministic enrichments (e.g., canonical CDSCO active substance name, RxNorm Concept Unique Identifier `RxCUI`, expanded vernacular posology translations in English, Hindi, and Marathi).
3. **`ModelPrediction` (`tier: "model_prediction"`):**
   - Machine inference outputs generated by experimental AI models. **Strictly prohibited in Phase 3**; reserved for Phase 6+.
4. **`HumanReviewLabel` (`tier: "human_review"`):**
   - Clinician or pharmacist adjudication flags and human verification actions.

## 4. Deterministic Clinical Normalization Rules

Evaluation and benchmarking require reproducible, deterministic text and posology normalization. Transformations are implemented in `backend/app/dataset/normalization.py`:

- **Unicode Normalization:** NFKC normalization decomposes ligature anomalies while recomposing canonical characters.
- **Whitespace Collapsing:** Replaces non-breaking spaces, line feeds, and multiple spaces with a single standard ASCII space.
- **Dosage Preservation Rule:**
  - Standardizes units (`mg`, `mcg`, `g`, `ml`, `tab`, `cap`, `puffs`, `drops`, `IU`).
  - **Safety Critical:** Never rounds, truncates, or converts floating-point dosages (e.g. `0.5 mg` remains `0.5 mg`; `1.0 mg` does not alter into `10 mg`).
- **Frequency Shorthand Standardization:**
  - Standardizes Latin abbreviations and numeric Indian clinical formats:
    - `1-0-1`, `BD`, `b.i.d.`, `BID` $\rightarrow$ `BD` ("Twice daily")
    - `1-1-1`, `TDS`, `t.i.d.`, `TID` $\rightarrow$ `TDS` ("Three times daily")
    - `1-0-0`, `0-1-0`, `OD`, `QD` $\rightarrow$ `OD` ("Once daily")
    - `0-0-1`, `HS`, `QHS` $\rightarrow$ `HS` ("At bedtime")
    - `SOS`, `PRN` $\rightarrow$ `SOS` ("As needed / when necessary")
    - `PC` $\rightarrow$ `PC` ("Post cibum / After food")
    - `AC` $\rightarrow$ `AC` ("Ante cibum / Before food")

## 5. Group-Aware Splitting & Leakage Prevention

Splitting prescription datasets randomly by image file introduces catastrophic data leakage because multiple images often originate from the same physician pad, clinic notebook, or patient encounter.

- **Group Key:** Every document record specifies a `patient_group_id`.
- **Isolation:** `GroupAwareSplitter` partitions entire groups as indivisible clusters into `train`, `val`, and `test` subsets.
- **Verification:** `detect_split_leakage()` statically verifies that no group ID or image SHA-256 hash intersects between any two partitions.

## 6. How to Audit & Validate Data

Run the automated CLI validation tool:

```bash
python scripts/validate_dataset.py
```

The tool performs static verification of:
1. `data/manifests/dataset_manifest.json` schema and URL validity.
2. `data/annotations/sample_annotations.json` ground truth conformance.
3. Physical image file existence, image stream readability, dimensions, and SHA-256 cryptographic match.
4. Duplicate image detection across document records.
5. Partition integrity and leakage across `train`, `val`, and `test` splits.
